## 2. 中途监控（可选，每 20 分钟一次）

```bash
grep -c 'fitness' ~/score_run.log              # 已完成评估次数，应持续增长
grep 'new best' ~/score_run.log | tail -3      # 只应在 Gain>=41 的点上出现
grep -o 'UGB=[0-9.e]*' ~/score_run.log | sort -t= -k2 -g | tail -2
tail -3 ~/score_run.log
```

**正常现象**（不要误判为出错）：
- `fitness` 一万多 → 增益没到 41 dB，被门槛罚了，正常
- 末尾大量 `TIMEOUT-SKIP` → 预算用完，正常收尾
- 大量 `Simulation run started.` 刷屏 → MDE 异步输出，无害

**异常信号**（出现就停下贴日志）：
- `Best param file not exists`
- `pythone: command not found`
- `optimization process has exited`（开跑 2 分钟内）
- 连续 10 分钟 `grep -c fitness` 不增长

## 附：常见异常处置

| 现象 | 原因 | 处置 |
|---|---|---|
| `pythone: command not found` | 没 source setup.bash | 见第 1 节 |
| `Best param file not exists` | 脚本没写出 best | 停下，检查 `[P0-4]` 日志行 |
| 跑完 score 全是 0 | 同上 | 同上 |
| `TOTAL` 远小于 6900 s | 有效点太多被 TIMEOUT-SKIP 提前吃掉预算 | 正常；说明 `t_eval` 比预估大 |
| `Total score` 略低于 82.16 | 随机种子/预算不同 | 只要 ≥78.27 就保留，不重跑 |
| 提示 `2026_EDA_case2: Invalid Lib Path` | 找不到隐藏电路库 | 无害，忽略 |
