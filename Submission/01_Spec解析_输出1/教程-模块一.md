## 1. 先分清：这次用的是「智能体」，不是「调一次模型」

赛题原文（五、赛题描述）把模块一写成「自然语言 Spec 解析（**智能体**）」，八、参赛平台又要求
「第1,2**智能体**部分，本地部署」+「指定大语言模型 Qwen3.8-Max，使用 APIKey 调用」。

所以正确形态是**智能体**，而不是"写个脚本调一次大模型"。两者差别：

| | 单次调用脚本 | **智能体（本教程用的）** |
|---|---|---|
| 流程 | 一次 prompt → 解析 JSON → 校验 | **决策循环**：思考 → 选工具 → 执行 → 观察 → 再决策 |
| LLM 角色 | 全部逻辑都在 prompt 里 | LLM 是**决策者**，具体活儿交给工具 |
| 工具 | 无（逻辑写死在代码里） | **工具注册表**，LLM 可通过 function calling 调用 |
| 无 API Key | 直接报错退出 | **回退确定性工具链**，照样出合规产物 |
| 推理链 | 只有"调用次数 + 原始输出" | 每步记 **thought / action / observation / decision / source** |

现在的实现长这样（第 8 步会讲代码）：

```
任务 → System Prompt → ┌─ LLM 决策（Qwen3.8-Max，function calling）─┐
                       │        ↓ 选工具                              │
                       │   工具执行（确定性 Python）                   │
                       │        ↓ 观察结果                            │
                       └──── 循环至 finalize ────────────────────────┘
                                    ↓
                        CoT 推理链（JSONL）+ 交付物
```

## 5. 第 4 步：配置 API Key（关键，最容易错）

**原则：Key 绝不写进代码/配置文件，只放环境变量。**

### 5.1 临时设置（只对当前窗口有效，推荐先用这个）

```powershell
$env:DASHSCOPE_API_KEY = "sk-你的Key"
```

验证设进去了没有（**只打印长度，不要打印全文**）：

```powershell
$env:DASHSCOPE_API_KEY.Length
```

能打印出数字（一般 30 多）就对了。

### 5.2 永久设置（确认能跑通后再做）

```powershell
setx DASHSCOPE_API_KEY "sk-你的Key"
```

> `setx` 之后**必须关掉 PowerShell 重新开**才生效。

### 5.3 三个必知的坑

| 坑 | 现象 | 原因 / 解决 |
|---|---|---|
| Key 与地域不匹配 | `401 Incorrect API key provided` | 你的网关是 **cn-beijing**，Key 必须在**华北2（北京）**业务空间里创建 |
| Key 没生效 | 日志里仍 `"used_llm": false` | 用了 `setx` 没重开终端，或当前窗口没设临时变量 |
| 网关地址/模型名不对 | 连接失败或 404 | 改 `agent/config.json` 里的 `llm.base_url` / `llm.model` |

**你的网关配置已经写进 `agent/config.json` 了**，不需要再改：

```json
"llm": {
  "model": "qwen3.8-max",
  "base_url": "https://ws-r96l7kx7y1u2cnpy.cn-beijing.maas.aliyuncs.com/compatible-mode/v1",
  "api_key_env": ["DASHSCOPE_API_KEY"],
  "temperature": 0.2,
  "timeout_s": 120,
  "max_retries": 3
}
```

> 配置里**只写环境变量名**，不写 Key 本身。检查一遍：`config.json` 里不该出现 `sk-` 开头的字符串。

## 7. 第 6 步：自检（这一步直接决定那 10 分）

打开 `agent\spec_case1.json`，逐条打勾：

- [ ] 有 `design_type`（电路类型）
- [ ] 有 `constraints`，且**每一项都同时有** `name / op / value / unit / type / priority`
- [ ] 有 `objectives`，且**每一项都同时有** `name / direction / unit / priority`
- [ ] 有 `pvt_condition` 和 `worst_case`
- [ ] 需求里说的"增益尽可能大"→ 出现在 `objectives`（**方向型描述是优化目标**）
- [ ] "不得低于 40dB" → 出现在 `constraints`（**阈值型描述是硬约束**）
- [ ] 需求里**没写**但赛题要卡的底线，被补齐了：`Phase_Margin >= 50 deg`、`Gain_Margin <= -10 dB`、`I_OPA <= 3 mA`
- [ ] 单位没有空字符串
- [ ] 没有 `null` 值

Select-String -Path output\trace_spec.jsonl -Pattern "validate_spec_schema|check_grading_gates|emit_structured_spec"

三步都出现 = 四要素校验、打分门槛核对、结构化产出都做了。

## 8. 第 7 步：看懂智能体代码（写报告用）

### 8.1 入口 `agent/agent.py`（约 130 行）

只做三件事：**读配置 → 建智能体 → 跑**。真正的逻辑在 `lib/`。

```powershell
& $PY agent.py spec      --input 需求.txt --out spec_case1.json   # 模块一
& $PY agent.py topology  --netlist 网表.netlist --outdir output    # 模块二（同架构，已内置）
& $PY agent.py self-test                                           # 离线自检
& $PY agent.py dump-config --out cfg.json                          # 导出配置（Key 已打码）
```

### 8.2 决策循环 `lib/agent_runtime.py`

```python
# 伪代码，看懂这个就懂智能体了
messages = [system_prompt, user_prompt]
for step in range(max_steps):
    resp = llm.chat(messages, tools=tool_schemas)      # ① 让模型决策
    if resp.tool_calls:                                 # ② 模型选择调用工具
        for tc in resp.tool_calls:
            obs = registry.call(tc.name, tc.args)       # ③ 执行工具
            log.add(thought, action, obs, ...)          # ④ 记进推理链
            if tc.name == finalize: return obs          # ⑤ 结束
    else:
        messages.append(...)                            # 模型直接给了 JSON 或没动作
```

**关键设计**：`source` 字段标出每步是 `llm`（模型决策）/ `fallback`（无 Key 的确定性策略）/ `agent`（自身编排），
评审能一眼看出哪些是模型的功劳、哪些是兜底。

### 8.3 六个工具 `lib/spec_agent.py`

| 工具 | 作用 |
|---|---|
| `parse_requirement` | 规则引擎做确定性解析，给模型一个可核对的基线 |
| `normalize_metric_unit` | 口语化指标名/单位 → 规范名 + 规范单位（防"漏单位"） |
| `validate_spec_schema` | 按教程 10.2 校验四要素（防"漏一类扣 1 分"） |
| `check_grading_gates` | 核对 PM/GM/I_OPA/DC_Gain 门槛是否齐备 |
| `lookup_device_bounds` | 取器件取值范围，供模块三用 |
| `emit_structured_spec` | **finalize**：产出最终 JSON |

### 8.4 推理链格式 `output/trace_*.jsonl`

每行一个独立 JSON：

```json
{"trace_id":"spec-20261011-205432","agent":"EDA-Spec-Agent","model":"qwen3.8-max",
 "used_llm":false,"step":1,"thought":"接收任务，准备解析输入并规划执行步骤",
 "action":"receive_task","action_input":{"requirement_text":"IC设计目标：..."},
 "observation":"任务已接收","decision":"进入智能体决策循环","source":"agent","elapsed_s":0.095}
```

`thought` 那一列就是报告要的"**每一步决策依据**"。

## 10. 常见报错速查

### 10.1 一键脚本相关（本机实际踩过的）

| 报错 / 现象 | 真正原因 | 解决 |
|---|---|---|
| `'o' 不是内部或外部命令`、`'︽帓鏌ャ€?' 不是内部或外部命令`（一串乱码命令） | **`.bat` 里有中文**。CMD 按 GBK 解析 .bat，中文行被当命令执行 | 保持 `.bat` 纯 ASCII；中文放 `.ps1` |
| `The string is missing the terminator: '` | **`.ps1` 无 UTF-8 BOM**。PowerShell 5.1 按 GBK 读，中文串解析失败 | 用「UTF-8 with BOM」保存 .ps1 |
| `python --version` 没反应 / 弹出应用商店 | `python` 解析到**微软商店占位存根** | 用完整路径，或用一键脚本（会自动跳过存根） |
| `[FAILED] no working Python found` | 脚本没找到可用 Python | 编辑脚本里的候选路径，或装个真 Python |
| 中文显示成 `��д��:` | Python 输出 UTF-8，控制台是 GBK | 跑之前设 `$env:PYTHONIOENCODING = "utf-8"`（一键脚本已内置） |

### 10.2 智能体运行相关

| 报错 / 现象 | 原因 | 解决 |
|---|---|---|
| 日志里一直 `"used_llm": false` | Key 没设 / 没重开终端 | 重做第 4 步 |
| `401 Incorrect API key provided` | Key 与 cn-beijing 地域不匹配 | 去华北2（北京）业务空间重建 Key |
| 连接超时 / Connection error | 网络 | 换网络（手机热点）试；确认网关地址没写错 |
| `ModuleNotFoundError: openai` | —— | **不需要 openai**！本智能体只用标准库，报这个说明你在跑旧脚本，换 `agent.py` |
| `ImportError: attempted relative import` | 包只复制了一部分 | 确认 `agent/lib/` 有 12 个模块 + `__init__.py` |
| 结果每次不一样 | 模型随机性 | `config.json` 里把 `temperature` 调低（现为 0.2，可调 0.1） |
| 输出被截断 | 输出过长 | 可调大 `timeout_s` |

## 附 A：为什么不用 `openai` 库

| | 用 `openai` 库 | **本智能体（纯标准库）** |
|---|---|---|
| 依赖 | 需要 `pip install openai` | **零依赖** |
| 评审环境 | 缺包就跑不起来 | 拿到就能跑 |
| function calling | 需要版本兼容 | 自己拼 JSON，完全可控 |

两者调的是**同一个网关、同一个模型**，协议都是 OpenAI 兼容的 `/chat/completions`。

## 附 B：为什么不用 `/apps/anthropic` 那个地址

你给的两个地址里：

- `.../compatible-mode/v1` → **OpenAI 兼容接口**（本智能体用这个）
- `.../apps/anthropic` → **Anthropic 兼容接口**，协议不同

**不要混用**，否则报协议不匹配。本智能体统一用第一个。
