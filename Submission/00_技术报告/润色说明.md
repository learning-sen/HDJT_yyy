## 一、改了什么

改写范围限于 `para()`、`bullet()`、`caption()` 三类散文共 70 段，其中 64 段换了写法，6 段基本沿用原句（都是很短的功能性句子，改了反而显得刻意）。排版函数 `set_font()` 及 `w:eastAsia` 设置一字未动，字体仍为正文宋体、标题黑体。

整篇的改动集中在四件事：

1. **过渡词换掉**。v1 的"其一/其二/其三""第一…第二…""理由有三"这类编号式衔接基本拆散，换成"三条理由：…""一个是…另一个是…""最外一层…中间一层…最里一层"等更贴近口语的推进方式。
2. **句式拆合**。长句按语义断点切开，短句有几句并成一句，句长分布因此更散：全篇句子数由 142 增至 157，平均句长由 53.1 字降到 47.4 字，标准差基本持平（27.9 → 28.1）。
3. **词换准，不换花**。尽量选工程语境里更常见的动词（"扛住""压下去""摊到""对得上账""退成"），不用形容词堆叠。
4. **删固定模板**。全文已无"值得注意的是""综上所述""不仅…而且""通过…实现"一类套话；另用脚本对"首先/其次/此外/因此/综上/不仅/而且/在…方面/通过…实现"等模式扫了一遍，命中段落数为 0。

按章举五处：

| 位置 | 改前 | 改后 | 理由 |
|---|---|---|---|
| §2.2 表后 | 一个必须写进文档的坑：服务器上的解释器不叫 python，而叫 pythone，且必须先 source setup.bash 才会出现在 PATH 中。 | 有个坑值得写进文档：服务器上的解释器不叫 python，叫 pythone，还得先 source setup.bash，它才会出现在 PATH 里。 | "必须写进文档的坑"是报告口吻的自我指涉；改成"有个坑值得写进文档"更像人在交代经验。原句一句到底，拆成两个短句后停顿自然。 |
| §4.3 表后 | "对称"与"匹配"是两个不同概念，这一点是模块二的一个关键判断。对称是图论性质（交换后网表完全等价），匹配是工艺性质（版图上需要一致以抑制失配，但电路上并不等价）。 | "对称"和"匹配"不是一回事，这是模块二最关键的一个区分。对称是图论性质：把两个器件对调，网表完全等价。匹配是工艺性质：版图上必须做一致才能压住失配，电路上却并不等价。 | 原文把定义塞在括号里，读起来像注释；改成冒号引出、两句并列，定义与判据分开了，技术含义没变。 |
| §5.3 | 两个细节决定了最终分数。第一，预算必须夹在 7200 秒以内：…第二，仿真失败必须不崩：…触发 KeyError，整轮优化直接终止——官方参考包就是这样 14 秒"正常退出"并留下 0 分的。 | 最终分数被两个细节决定。一个是预算必须夹在 7200 秒以内：…另一个是仿真失败时不能崩：…KeyError 一抛，整轮优化就断了——官方参考包正是这样跑了 14 秒"正常退出"，留下 0 分。 | "第一/第二"是最典型的模板衔接；换成"一个是/另一个是"后因果链仍逐条对应，数值（7200、0.80×10800=8640、3.3、14、0）全部原位保留。 |

- §9.3 的"这个判断后来直接决定了…也直接带来了…"改为"落到…三处修正上，也直接撑起了…"，避免两个"直接"重复。

| 对象 | 处置 | 原因 |

| 全部数字、单位、比值 | 一字未动 | 数值是评分依据，任何"顺手四舍五入"都会让报告与产物对不上。自检用正则抽取全文数字做多重集比对，结果为空差异。 |
| 22 张表格的每一个单元格（含表头） | 一字未动 | 表格是数据，不是散文。逐格比对差异为 0。 |
| 全部代码块、命令、JSON、日志片段（47 行等宽文本） | 一字未动 | 命令可复制即用，日志片段是证据原件，改一个字就失真。 |
