# 模块三修正说明（2026-10-18）

本文件记录模块三（基于约束的多目标尺寸优化）在拿到服务器原件 `server/` 之后做的修正。
每条都写清**为什么改、改在哪、影响什么、怎么验证**。

依据链：`server/run_score.sh`（评测包装）与 `server/score.py`（评分器本体）是**唯一真相来源**；
赛题 PDF 的 6.3 评分表是"最终排名口径"，与平台自动分**不是同一套数**。

---

## 0. 一句话结论

提交版的**接口签名和参数文件格式本来就是对的**（能进评分器），
问题集中在**数字口径**：时间预算超了满分区、搜索边界与评分器的 clamp 不一致、
回写漏了三个参数、以及分组对 Hidden 电路有硬编码风险。

## P0-2 时间预算超出"时间分满分区"

| 项 | 内容 |
|---|---|
| 问题 | `BUDGET_RATIO=0.80` × `TIME_LIMIT=10800` = **8640 s**，但 `score.py` 的 `time_base=7200`，超过即按 `7200/t×20` 线性掉分 |
| 依据 | `score.py` L447-450；`run_score.sh` L73 传 `--time_base 7200.0` |
| 改动 | 新增 `TIME_FULL_SCORE=7200.0`、`TIME_SAFETY=300.0`；预算取 `min(ratio×limit, 6900)` 并打印压缩日志 |
| 影响 | 优化可用时间由 8640 s 降到 **6900 s**（少约 20% 代数），换来时间分从 ≈16.7 回到 20 |
| 验证 | 自测 T4 段日志出现 `[P0-2]`（仅在触发压缩时打印，默认 10800 会触发） |

## P0-3 搜索边界与评分器的 clamp 不一致

| 项 | 内容 |
|---|---|
| 问题 | 上游模板对所有连续参数统一用 `0.13..20`；`score.py::read_parameters` 却按参数名分别 clamp |
| 依据 | `score.py` L114-149：`m`/`segments` 整数 1..100；`l`（电容）4..30；`l` 其余 0.13..20；`fw` 0.15..50；`segW` 0.42..10；`segL` 5..100 |
| 改动 | 新增 `_bounds_for()` 与 `_patched_read_parameters()`，取同样的区间、同样用 clamp；在 PATCH 末尾重新绑定全局 `read_parameters` |
| 影响 | **优化空间 == 评分空间**。此前 `segL` 在 0.13..5 区间探索的点会被评分器 clamp 到 5，等于白跑 |
| 验证 | 自测输出 `[P0-3] Read 105 parameters (bounds aligned with score.py)`，T2a/T3a/T3b 全 PASS |

## P0-4 回写口径（**已按真实参数文件修订，第一版方向错了**）

| 项 | 内容 |
|---|---|
| 第一版问题 | 上游 `extract_params()` 只写 MOS 的 `m/l/fw`、电阻的 `segW/segL`、电容的 `l`。我据此以为"漏了轮廓参数"，于是加了 `R*_segments`、`C*_fw`、`C*_m` |
| **为什么错了** | 拿到真实的 `case1_params_0.txt` 后核对：**105 = MOS 29×3 + 电容 6×1 + 电阻 6×2**。电容**只有 `l`**、电阻**只有 `segL/segW`**，根本没有 `segments`/`fw`/`m`。`score.py::calc_area` 里的 `fw/m/segments` 是它**从电路 CV 直接读**的，与参数文件无关 —— 我从 `calc_area` 反推参数文件 schema，属于误推 |
| 修订后 | 改为**schema 驱动**：`read_parameters` 时记住输入文件的变量清单（`INPUT_SCHEMA`），回写时严格按同一清单、同一顺序逐项取 CV 值写出。另留 `OPT_EXTRA_PARAMS=1` 供实验追加，默认关闭 |
| 影响 | 回写文件与初始解 schema **完全一致**，不会偷偷改变赛方的参数化口径 |
| 验证 | 用真实文件校验：105 个变量**全部落在 P0-3 的边界内**（越界 0）；`segments`/`C*_fw` 计数均为 0，印证 schema；自测 T1~T5 仍全 PASS |

## P0-7 参考实现实跑结果是 **0 分**（新发现，关键）

`server/run_score_sh_result.txt` 是官方参考包的一次真实评测输出：

```text
[INFO] Optimization script ended normally
[INFO] Execution duration: 00:00:14 (14 seconds)
...
Best param file not exists!!!!
PM/GM/Gain/I_OPA/UGB/Area/Time score : 0.0000    ->  Total score : 0.0000
```

| 事实 | 含义 |
|---|---|
| 参考包**没写出** `2026_EDA_case1_best_params.txt` | 不写这个文件 = **直接 0 分**，与优化质量无关 |
| 只跑了 **14 秒**就正常退出 | 参考 `optimization.py` 在不带 `--use_algorithm_de` 时不进优化循环，等于什么都没做 |
| 顶层目录是 `eda_2025_case_1` | 官方压缩包本身就是 2025 包；`run_score.sh` 有"唯一子目录"兜底，所以目录名不叫 `eda_2026_case_1` 也能跑 |
| `command.txt` 不在 `/app/input/res/` | 实际走默认 MDE（`OPA_loopgain` / `spe_state1_Corner`），与 case1 一致 |
| 出现 `Unable to open library 2026_EDA_case2` | 有 case2 的痕迹，但本机 `circuits/` 里**只有 case1** |

> **这是当前最有价值的结论**：只要我们的脚本能稳定写出 schema 正确的 `best_params.txt`，
> 就已经从 0 分变成有分。P4 的兜底逻辑正好覆盖这一点。

## P0-8 MDE 配置里的旧机绝对路径（**"全员 0 分"的真正根因**）

| 项 | 内容 |
|---|---|
| 证据 | `server/2026_EDA_case1_optimization.log` L46-50：`Creating simulation netlist fails.` + `Simulation failed. Reason: "File does not exist: /home/eda_2025/EDA_2025_Empyrean_lab_start/hes_release/models/spectre/spe_demo.scs."` |
