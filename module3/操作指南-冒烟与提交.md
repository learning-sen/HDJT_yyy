## 0.5 每个新终端第一件事：`source setup.bash`

> **2026-10-18 真实踩坑（第二次冒烟）**：
> ```
> [edauser32@eda202601 eda_2025_case_1]$ time pythone optimization.py ...

> `pythone` **不是系统命令**，是 `setup.bash` 加进 PATH 的工具链命令：
> 脚本里把 `$AETHER_ROOT/bin`、`$ALPS_ROOT/bin`、`$IWAVE_ROOT/bin`、`$RCEXPLORER_ROOT/bin`、
> `$ARGUS_ROOT/bin` 依次塞进 `PATH`，同时设 `LM_LICENSE_FILE`、`PKG_ROOT`、
> `PYAE_VER=3.9`、`PYAETHER_HOME`。
>
> **不 source 的两个后果**：① 找不到 `pythone`；② 就算改用 `python` 启动成功，
> 也会在 `LC_Check out license` 处失败（拿不到 license）。
>
> `run_score.sh` 自己也是用 `pythone` 调脚本（L244 / L495），
> 所以**赛方评测环境一定是 source 过的**，我们也必须照样做。

```bash
source ~/EDA_2026_Empyrean_lab_start/setup.bash
which pythone          # 必须打印出路径；打不出来就别往下走
echo $LM_LICENSE_FILE  # 必须非空
```

`which pythone` 仍找不到时的排查顺序：

```bash
ls $AETHER_ROOT/bin | grep -i python
ls $ALPS_ROOT/bin   | grep -i python
find /home/PyAether_Packages -maxdepth 6 -name 'pythone*' 2>/dev/null | head
```

> ⚠️ **环境变量不跨 shell 继承**：每开一个新终端（或 VNC 重连）都要重新 `source`。
> 同理 `SMOKE` / `PKG` 这类自己起的变量也会丢，换终端后要重设。

### 1.2 临时目录：为什么不能用 `/tmp/smoke`（2026-10-18 真实踩坑）

实际执行时卡在这里：

```
[edauser32@eda202601 EDA_2026_Empyrean_score]$ rm -rf /tmp/smoke && mkdir -p /tmp/smoke
rm: cannot remove '/tmp/smoke/eda_2026_case_1/spec.json': Permission denied
```

**这不是你操作错了，是 `/tmp/smoke` 这个固定名字已经被别的账号占过了。**

关键点：**删除一个文件，看的是它「父目录」的写权限，跟文件自己的权限无关。**

`spec.json` 自己是 644 还是 777 都不影响——只要 `/tmp/smoke/eda_2026_case_1` 这个目录不归你、
也没对你开放写权限，你就删不掉它里面的任何东西。

| 目录 | 属主 | 你能删里面文件吗 |
|---|---|---|
| `/tmp/smoke/eda_2026_case_1` | 别人 | ❌ 不能（父目录只对属主可写） |
| `~/smoke/eda_2026_case_1` | 你 | ✅ 能 |

**另外三个必须知道的点：**

1. **`&&` 是短路的。** `rm -rf ... && mkdir -p ...` 里 `rm` 一失败，后面的 `mkdir` 根本不会执行。
   于是你以为目录建好了，其实没有，紧接着的 `tar -xzf` 也会连带失败，报错会一层层往下滚，
   很容易误判成"解包坏了"。

2. **`/tmp` 通常带 sticky bit**（`drwxrwxrwt`，注意权限末尾那个 `t`）。
   带 sticky 的目录里，**你只能删除自己拥有的条目**——所以连 `/tmp/smoke` 本身都可能删不掉。

3. **你没有 sudo。**
   ```
   [sudo] password for edauser32:
   edauser32 is not in the sudoers file.  This incident will be reported.
   ```
   这句是 sudo 的固定提示语（任何普通用户尝试 sudo 都会看到，**不用紧张**），但结论很清楚：
   **别人留下的 `/tmp/smoke`，你既清不掉、也修不了。别再跟它较劲。**

**结论：临时目录一律带自己的标识，或者干脆放家目录。** 上面命令里用的是 `SMOKE=~/smoke`。

想确认自己遇到的是不是这种情况，跑这条（**不需要 sudo**）：

```bash
ls -ld /tmp/smoke /tmp/smoke/eda_2026_case_1 /tmp/smoke/eda_2026_case_1/spec.json
```

看**第三列（属主）**。如果不是 `edauser32` → 就是上面这个原因，**换路径，别硬删**。

哪天拿到了 sudo，想顺手清掉它：

```bash
sudo rm -rf /tmp/smoke
```

> 附带好处：`/tmp` 在不少机器上是内存盘（tmpfs），容量有限。把解包目录放 `~/` 同时也避开了
> "解包把 /tmp 撑爆"这个隐患。
