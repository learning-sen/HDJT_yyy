# 模块一 从零到交付 · 手把手教程（Python 虚拟环境版）

> 目标：让一个没写过智能体的人，跟着做完能交出一个**完整的模块一**。
> 适用：**Windows + Python 3.12 + 项目根目录下的 `.venv` 虚拟环境** + 你已经拿到的 Qwen3.8-Max API Key。
> 阅读方式：**从上往下，做一步、验一步，别跳。**
> 与原版教程的唯一区别：**所有 Python 操作都在 `.venv` 虚拟环境里做**，不污染系统 Python。代码本身一模一样。

---

## 0. 这份教程和原版差在哪

| 环节 | 原版教程 | 本教程（虚拟环境版） |
|---|---|---|
| 装库 | `python -m pip install -U openai` 装进系统 Python | 先建 `.venv`，再 `.venv` 里装，系统 Python 保持干净 |
| 运行 | 直接 `python agent.py` | **先激活 `.venv`**，再 `python agent.py` |
| 环境可复现 | 靠记忆 + 报告里写一句 | `requirements.txt` 锁版本，评委/队友一条命令复原 |
| 交作业体积 | 无影响 | 提交时**不要打包 `.venv`**（几百 MB，用 `.gitignore` 排除） |
| 代码 | — | 与原版**完全相同**，仅多打印一行 `sys.executable` 用于确认环境 |

> **一句话原理**：虚拟环境就是一个放在项目里的"独立 Python 小盒子"（`.venv`）。激活它之后，你的 `python`、`pip` 都只作用于这个小盒子，装的库、换的版本都不会影响系统里其他项目。

## 1. 先搞清楚：模块一要交什么

| 编号 | 交付物 | 文件 | 对应分数 |
|---|---|---|---|
| ① | Spec 解析结果 | `spec_case1.json` | 10 分 |
| ② | 智能体源码 | `agent/agent.py` | （含在"源代码"提交项） |
| ③ | 配置文件 | `agent/config.json` | （报告里要写） |
| ④ | 系统提示词 | `system_prompt.txt` | （报告里要贴） |
| ⑤ | 推理链日志 | `agent/output/trace_*.jsonl` | （报告里要写决策依据） |

**判分口径**（来自赛题 PDF）：
> 自然语言 Spec 正确解析为 Json 结构化指标（10 分）。Json 文件需要包括**硬约束项、优化目标、指标单位及目标优先级**等信息，**每缺少一个扣 1 分**。

记住这句话：**单位、优先级漏了就是丢分。** 后面的自检清单就是按这句设计的。

## 4. 第 3 步：激活虚拟环境（最容易卡住的一步）

```powershell
& ".\.venv\Scripts\Activate.ps1"
```

成功后，命令行**前面会多出一个 `(.venv)` 前缀**，长这样：

```text
(.venv) PS C:\Users\HuangJS\Desktop\南邮作业\华大九天\HDJT_yyy>
```

**看到 `(.venv)` 才算激活成功。** 后面的所有命令都要在这个窗口里执行。

### 4.1 报"禁止运行脚本"怎么办

报错长这样：

```text
Activate.ps1 : 无法加载文件 ...\Activate.ps1，因为在此系统上禁止运行脚本。
```

原因：Windows 默认禁止运行 PowerShell 脚本。**一次性解决**（只影响当前用户，不需要管理员）：

```powershell
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
```

然后重新执行激活命令。

### 4.2 不想改执行策略的两种替代方案

**方案 A（推荐给怕麻烦的人）**——用 cmd 风格的批处理激活，不受脚本策略限制：

```powershell
cmd /k ".\.venv\Scripts\activate.bat"
```

**方案 B**——干脆不激活，直接用绝对路径调用 `.venv` 里的解释器：

```powershell
& ".\.venv\Scripts\python.exe" agent.py
```

> 方案 B 效果和激活完全等价，只是每次命令要多打一截路径。**后面所有 `python xxx` 都可以替换成 `& ".\.venv\Scripts\python.exe" xxx`。**

## 5. 第 4 步：在虚拟环境里装依赖

### 5.1 先确认 pip 指向的是 `.venv`

```powershell
python -c "import sys; print(sys.executable)"
```

**应该看到**：路径里有 `\HDJT_yyy\.venv\Scripts\python.exe`。

如果打出来的还是 `D:\Python3.12.10\python.exe`，说明**没激活成功**，回第 3 步。

### 5.2 建 `requirements.txt`

在项目根目录新建 `requirements.txt`，内容就一行：

```text
openai>=1.60.1,<2.0.0
```

> 为什么只写一行？因为 `openai` 会自动带上 `httpx`、`pydantic` 等依赖，不用手写。
> 为什么锁 `<2.0.0`？`openai` 2.x 有接口变动，锁住大版本可以保证队友复原出来的环境和你一样能跑。
> 为什么用 `openai` 这个库？因为阿里云百炼提供的是 **OpenAI 兼容接口**，换掉 base_url 和 model 就能直接调通义千问，不用学新 SDK。

### 5.3 升级 pip 并安装（国内网络建议加镜像）

```powershell
python -m pip install -U pip
python -m pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

**应该看到** 最后一行是 `Successfully installed openai-1.x.x ...`。

### 5.4 把镜像配置只写进这个虚拟环境（可选，但很干净）

```powershell
python -m pip config set --site global.index-url https://pypi.tuna.tsinghua.edu.cn/simple
```

> `--site` 是关键：配置只写进 `.venv`，不会改你系统全局的 pip 配置。这也是虚拟环境的好处之一。

### 5.5 验证安装

```powershell
python -c "import openai, sys; print(openai.__version__); print(sys.executable)"
```

**应该看到**：一行版本号（如 `1.60.1`），一行 `.venv` 里的路径。

### 5.6 冻结当前环境（交作业时用）

```powershell
python -m pip freeze > requirements.lock.txt
```

> 这份把**实际装到的所有依赖及精确版本**都写下来了。交作业时同时给 `requirements.txt`（人读）和 `requirements.lock.txt`（复现）。
>
> ⚠️ **Windows PowerShell 5.1 用户注意**：它的 `>` 默认写成 UTF-16，可能导致文件里出现乱码/空行。改用：
> ```powershell
> python -m pip freeze | Out-File -Encoding utf8 requirements.lock.txt
> ```

## 6. 第 5 步：配置 API Key（关键，最容易错）

**原则：Key 绝不写进代码文件、绝不写进 `config.json`、绝不写进 `.venv`，只放环境变量。**

### 6.1 临时设置（只对当前这个窗口有效，推荐先用这个试）

```powershell
$env:DASHSCOPE_API_KEY = "sk-你的Key"
```

**验证一下设进去没有**（注意：只打印长度，不要打印全文）：

```powershell
$env:DASHSCOPE_API_KEY.Length
```

能打印出数字（一般 30 多）就对了。

> ⚠️ **虚拟环境专属坑**：环境变量是**跟着窗口**的，不是跟着虚拟环境走的。关掉窗口 → 虚拟环境要重新激活 → **Key 也要重新设**。两个都别忘了。

### 6.2 永久设置（确认能跑通后再做）

```powershell
setx DASHSCOPE_API_KEY "sk-你的Key"
```

> `setx` 设置后**必须关掉 PowerShell 重新开**才生效（重新开之后还要再激活 `.venv`）。

### 6.3 两个必须知道的坑

| 坑 | 现象 | 原因 |
|---|---|---|
| Key 与地域不匹配 | `401 Incorrect API key provided` | 北京空间的 Key 打了别的地域的地址。**你的地址是 `cn-beijing`，所以 Key 必须是在华北2（北京）业务空间里创建的。** |
| Key 没生效 | 报"未找到 API Key" | 用了 `setx` 但没重开终端；或者重开了终端但没重设临时变量 |

### 6.4 千万别做这些事

- ❌ 把 Key 写进 `agent.py` → 提交后泄露，且违反"Key 不落盘"设计
- ❌ 把 Key 写进 `agent/config.json` → 同上，`api_key_env` 只写**变量名**
- ❌ 把 Key 写进 `.venv\Scripts\activate.bat` → 看起来很方便，实际是把密钥藏进了不提交的目录，**换台机器就失效**，而且哪天误交就把 Key 交出去了

## 8. 第 7 步：检查 / 补全提示词

打开 [system_prompt.txt](system_prompt.txt)，确认它已经存在（你已经有了）。

但**建议在文件末尾追加下面这三段**，能直接堵住三个丢分点（模型漏输出单位、漏优先级、漏赛题底线指标）：

```text
【默认底线补全规则】
当用户没有明确给出下列指标时，按赛题评分底线补成硬约束：
- Phase_Margin >= 50 deg
- Gain_Margin  <= -10 dB
- I_OPA        <= 3 mA
- DC_Gain      >= 40 dB

【口语映射规则】
- "稳定 / 不能振荡"      -> Phase_Margin、Gain_Margin 硬约束
- "低功耗 / 省电"        -> Power 最小化，且 I_OPA 硬约束
- "高增益 / 增益要大"    -> DC_Gain 最大化
- "大带宽 / 速度快"      -> UGB 最大化
- "面积小 / 省面积"      -> Area 最小化

【字段完整性（评分硬要求，缺一项扣 1 分）】
- constraints 每一项必须含：name, op, value, unit, type, priority
- objectives  每一项必须含：name, direction, unit, priority
- priority：1 表示最重要，数字越大越次要
```

> ⚠️ **注意**：你原来的提示词里，`constraints` 格式说明没写 `priority`、`objectives` 格式说明没写 `unit`，但你的样例 [spec_case1.json](spec_case1.json) 里两个字段都有——**规范和数据打架**，模型会随机漏。加上上面第三段就统一了。

## 9. 第 8 步：写 `agent.py`

在 `module1/agent/` 下新建 `agent.py`，**整段复制**下面的代码：

```python
# -*- coding: utf-8 -*-
"""
模块一：自然语言 Spec 解析智能体
运行方式（必须先激活虚拟环境，见教程第 3 步）：
    python agent.py                              # 用默认的需求文件
    python agent.py "C:\\path\\需求.txt"          # 指定需求文件
    python agent.py --check                       # 只检查环境，不调模型
"""
import json
import os
import re
import sys
import time
from pathlib import Path

from openai import OpenAI

HERE = Path(__file__).resolve().parent

# 赛题提供的需求文件（默认输入）
DEFAULT_INPUT = HERE.parent.parent / "extracted" / "赛题数据本身" / "全差分运放设计需求.txt"

# 指标 -> 默认单位（模型漏了单位时按这个补，补了会记进日志）
UNIT_DEFAULT = {
    "DC_Gain": "dB", "UGB": "MHz", "Phase_Margin": "deg", "Gain_Margin": "dB",
    "I_OPA": "mA", "Area": "um^2", "Slew_Rate": "V/us", "Power": "mW",
    "Output_Swing": "V", "Input_CM_Range": "V", "CMRR": "dB", "PSRR": "dB",
    "Noise": "nV/sqrt(Hz)", "Offset": "mV",
}


def load_config() -> dict:
    with open(HERE / "config.json", "r", encoding="utf-8") as f:
        return json.load(f)


def read_text(p: Path) -> str:
    return p.read_text(encoding="utf-8").strip()


def strip_code_fence(text: str) -> str:
    """模型有时会把 JSON 包在 ```json ... ``` 里，剥掉它。"""
    t = text.strip()
    m = re.search(r"```(?:json)?\s*(.*?)```", t, re.S)
    if m:
        t = m.group(1).strip()
    i, j = t.find("{"), t.rfind("}")
    if i != -1 and j > i:
        t = t[i:j + 1]
    return t


def check_spec(spec: dict) -> list:
    """检查评分要求的字段是否齐全，返回缺失项列表（空=通过）。"""
    missing = []
    for k in ("design_type", "constraints", "objectives", "pvt_condition", "worst_case"):
        if k not in spec:
            missing.append(k)
    for i, c in enumerate(spec.get("constraints") or []):
        for k in ("name", "op", "value", "unit", "type", "priority"):
            if k not in c:
                missing.append(f"constraints[{i}].{k}")
    for i, o in enumerate(spec.get("objectives") or []):
        for k in ("name", "direction", "unit", "priority"):
            if k not in o:
                missing.append(f"objectives[{i}].{k}")
    return missing


def autofill(spec: dict) -> list:
    """把模型漏掉的字段补上，返回补了哪些（会写进日志，报告里要交代）。"""
    filled = []
    for i, c in enumerate(spec.get("constraints") or []):
        if "unit" not in c:
            c["unit"] = UNIT_DEFAULT.get(c.get("name"), "")
            filled.append(f"constraints[{i}].unit -> {c['unit']}")
        if "type" not in c:
            c["type"] = "hard"
            filled.append(f"constraints[{i}].type -> hard")
        if "priority" not in c:
            c["priority"] = i + 1
            filled.append(f"constraints[{i}].priority -> {i + 1}")
    for i, o in enumerate(spec.get("objectives") or []):
        if "unit" not in o:
            o["unit"] = UNIT_DEFAULT.get(o.get("name"), "")
            filled.append(f"objectives[{i}].unit -> {o['unit']}")
        if "priority" not in o:
            o["priority"] = i + 1
            filled.append(f"objectives[{i}].priority -> {i + 1}")
    return filled


def ask_model(client, cfg, system_prompt, requirement, feedback=""):
    user = f"【设计需求】\n{requirement}"
    if feedback:
        user += f"\n\n【上一次输出不合法，请修正后重新只输出 JSON】\n{feedback}"
    resp = client.chat.completions.create(
        model=cfg["model"],
        messages=[
            {"role": "system", "content": system_prompt},
            {"role": "user", "content": user},
        ],
        temperature=cfg.get("temperature", 0.2),
        max_tokens=cfg.get("max_tokens", 4096),
        timeout=cfg.get("timeout_s", 120),
    )
    return resp.choices[0].message.content or ""


def resolve_input() -> Path:
    """取需求文件路径：忽略 --check 这类开关，只认第一个非 -- 开头的参数。"""
    args = [a for a in sys.argv[1:] if not a.startswith("--")]
    return Path(args[0]).resolve() if args else DEFAULT_INPUT


def preflight(cfg, in_path: Path) -> int:
    """跑模型之前先自检环境：解释器、依赖、Key、需求文件。"""
    print(f"Python    : {sys.executable}")
    in_venv = sys.prefix != getattr(sys, "base_prefix", sys.prefix)
    print(f"虚拟环境  : {'是 (.venv 生效)' if in_venv else '否（正在用系统 Python！请先激活 .venv）'}")
    print(f"模型      : {cfg['model']}")
    print(f"接口      : {cfg['base_url']}")

    key = os.getenv(cfg["api_key_env"], "")
    if not key:
        print(f"[错误] 环境变量 {cfg['api_key_env']} 没设置。")
        print('请在 PowerShell 里执行：$env:DASHSCOPE_API_KEY = "sk-你的Key"')
        return 1
    print(f"API Key   : 已设置（长度 {len(key)}，不打印内容）")

    if not in_path.exists():
        print(f"[错误] 找不到需求文件：{in_path}")
        return 1
    print(f"需求文件  : {in_path}")
    return 0


def main():
    cfg = load_config()
    in_path = resolve_input()

    # 0) 环境自检
    if preflight(cfg, in_path) != 0:
        sys.exit(1)
    if "--check" in sys.argv:
        print("\n[自检通过] 环境没问题，去掉 --check 就能真正调用模型。")
        return

    key = os.getenv(cfg["api_key_env"])
    client = OpenAI(api_key=key, base_url=cfg["base_url"])
    system_prompt = read_text((HERE / cfg["prompt_file"]).resolve())

    # 1) 取输入
    requirement = read_text(in_path)
    print("-" * 60)

    # 2) 调用 + 校验 + 重试
    out_dir = (HERE / cfg["output_dir"]).resolve()
    out_dir.mkdir(parents=True, exist_ok=True)
    stamp = time.strftime("%Y%m%d-%H%M%S")
    trace_path = out_dir / f"trace_{stamp}.jsonl"

    spec, filled, missing, raw = None, [], [], ""
    for attempt in range(1, cfg.get("max_retries", 3) + 1):
        print(f"[第 {attempt} 次调用] ...")
        try:
            raw = ask_model(client, cfg, system_prompt, requirement,
                            feedback="; ".join(missing))
        except Exception as e:
            print(f"  调用失败：{e}")
            with open(trace_path, "a", encoding="utf-8") as f:
                f.write(json.dumps({"attempt": attempt, "error": str(e)},
                                   ensure_ascii=False) + "\n")
            time.sleep(2)
            continue

        with open(trace_path, "a", encoding="utf-8") as f:
            f.write(json.dumps({
                "attempt": attempt, "time": time.strftime("%Y-%m-%d %H:%M:%S"),
                "model": cfg["model"], "input": requirement, "raw_output": raw,
            }, ensure_ascii=False) + "\n")

        try:
            spec = json.loads(strip_code_fence(raw))
        except json.JSONDecodeError as e:
            missing = [f"输出不是合法 JSON：{e}"]
            print(f"  JSON 解析失败：{e}")
            continue

        missing = check_spec(spec)
        if not missing:
            break
        print(f"  缺字段：{missing}")

    if spec is None or missing:
        print("\n[失败] 重试用完仍未拿到完整 JSON，请把上面的错误信息发我。")
        sys.exit(1)

    filled = autofill(spec)

    # 3) 落盘
    spec_file = out_dir / f"spec_{stamp}.json"
    spec_file.write_text(json.dumps(spec, ensure_ascii=False, indent=2), encoding="utf-8")
    # 同时写一份固定名，方便直接当交付物
    (out_dir / "spec_case1.json").write_text(
        json.dumps(spec, ensure_ascii=False, indent=2), encoding="utf-8")
    (HERE.parent / "spec_case1.json").write_text(
        json.dumps(spec, ensure_ascii=False, indent=2), encoding="utf-8")

    if filled:
        with open(trace_path, "a", encoding="utf-8") as f:
            f.write(json.dumps({"autofill": filled}, ensure_ascii=False) + "\n")

    print("-" * 60)
    print(f"[成功] 解析结果：{spec_file}")
    print(f"       推理日志：{trace_path}")
    if filled:
        print(f"       自动补全了 {len(filled)} 个字段（已记入日志）")
    print("\n--- JSON 预览 ---")
    print(json.dumps(spec, ensure_ascii=False, indent=2))


if __name__ == "__main__":
    main()
```

**代码在干什么**（看懂这几句就够写报告了）：

1. **`preflight()` 先自检环境**（虚拟环境版新增）：打印真正在跑的 Python 路径、判断 `.venv` 有没有生效、Key 有没有设、需求文件在不在——**99% 的翻车都在这四项里**，提前报出来比对着 `401` 干瞪眼强
2. 从 `config.json` 读模型名、地址、Key 的环境变量名 → **Key 不落盘**
3. 读 `system_prompt.txt` 当 system 消息，需求文本当 user 消息
4. 拿到回复后**先剥 markdown 代码块，再解析 JSON**
5. **校验字段**（硬约束/优化目标/单位/优先级），缺了就带着"缺什么"再问一次
6. 还缺的用 `autofill` 兜底补上，**并且把补了什么记进日志**（这一步就是报告里"为什么这么解析"的证据）
7. 输出 `spec_时间戳.json` + 固定名 `spec_case1.json` + 推理日志 `trace_*.jsonl`

> 新增了 `--check` 开关：**只做环境自检、不花 API 额度**。写完代码先跑这个，比直接跑主流程省心得多。

## 附 C：为什么要折腾虚拟环境（答辩可能会问）

| 问题 | 回答 |
|---|---|
| 虚拟环境解决了什么痛点？ | 不同赛题/项目依赖的库版本会打架。虚拟环境让每个项目有独立的 `site-packages`，A 项目锁 `openai 1.x`，B 项目用 `2.x`，互不影响，也不用管理员权限。 |
| 会不会让提交变复杂？ | 不会。`.venv` 不提交，只交 `requirements.txt`；评委一条 `pip install -r requirements.txt` 就能复原一模一样的环境。 |
| 和 conda 比呢？ | 本赛题只需要 Python 包，`venv` 是标准库自带、零额外安装，最轻。conda 更适合需要非 Python 二进制依赖（如 CUDA）的场景。 |
| 怎么证明环境是可复现的？ | 报告里贴三样：`python --version`、`pip list` 或 `requirements.lock.txt`、以及 `agent.py` 打印出的 `sys.executable`（证明虚拟环境生效）。 |

## 附 D：为什么不用 `/apps/anthropic` 那个地址

- `.../compatible-mode/v1` → **OpenAI 兼容接口**，用 `openai` 库调
